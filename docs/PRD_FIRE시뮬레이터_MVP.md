# PRD — Firedom (파이어덤) MVP
## 한국형 FIRE 시뮬레이터

작성일: 2026-07-08 | 버전: v0.9 (초안) | 플랫폼: Flutter (iOS/Android) | 아키텍처: 로컬 우선, 서버리스

---

## 1. 문제 정의

한국의 FIRE 지향 유저는 "계산은 낙원계산기(웹), 기록은 엑셀/수기 앱"으로 도구를 쪼개 쓰고 있으며, **세운 계획과 매달의 실제 자산이 연결되지 않는다.** 계획 대비 내가 어디쯤 와 있는지 확인할 방법이 없어 수년짜리 여정에서 동기가 끊기고 기록이 중단된다. 기존 웹 계산기는 1회성이고, 토스·뱅크샐러드는 '현재 잔고' 중심이라 미래 설계와 궤도 추적이 없다 (근거: 경쟁분석 문서 참조).

## 2. 제품 원칙 (모든 스펙 판단의 기준)

1. **계산기가 아니라 궤도 추적기다.** 핵심 루프: 목표 설계 → 시뮬레이션(계획 궤도) → 월 스냅샷 기록 → 궤도 비교 → 조정
2. **기록은 무료, 통찰은 유료.** 기록 루프에 과금하지 않는다
3. **데이터는 기기에만.** 서버 없음, 계정 없음(MVP). 프라이버시가 포지셔닝
4. **행동 지시 금지.** "리밸런싱하세요"가 아니라 "목표 배분 대비 -5%p" — 사실 표시까지만 (투자자문 규제 회피)
5. **월 1회 수기 입력은 버그가 아니라 리추얼이다.** 자동연동으로 가계부와 경쟁하지 않는다

## 3. 목표 (성공 기준)

- **G1. 활성화**: 첫 실행 → "나의 FIRE 나이" 확인 완료율 ≥ 60% (온보딩 퍼널)
- **G2. 핵심 습관**: 온보딩 완료 유저의 첫 스냅샷 기록률 ≥ 50%, 2개월 연속 기록률 ≥ 35%
- **G3. 리텐션**: M2 리텐션 ≥ 25% (월 1회 앱 특성 반영, MAU 기준)
- **G4. 수익**: 활성 유저의 유료 구독 전환율 3~5% (출시 3개월 시점)
- **G5. 스토어 평점 4.5+ 유지** (민감 데이터 앱은 신뢰가 전부)

## 4. Non-Goals (v1에서 의식적으로 버리는 것)

- **마이데이터/오픈뱅킹 자동 연동** — 허가제·중계 API 비용. 수기 스냅샷이 제품 정체성
- **커뮤니티·챌린지·익명 벤치마크** — 콜드 스타트, 모더레이션 비용, 가계부 정체성으로의 표류. 벤치마크는 데이터 축적 후(1년+) 재검토
- **일 단위 가계부/소비 트래킹** — 토스·뱅크샐러드의 링. 소득/지출은 월 합계 2개 필드만
- **투자 추천·리밸런싱 지시** — 투자자문업 규제. 사실 표시까지만
- **자체 백엔드 서버** — 멀티디바이스 동기화·벤치마크 수요가 검증되면 v1.x에서 Spring Boot로
- **은퇴 후 인출 모드 + 절세 인출 순서 시뮬(ISA→연금저축→IRP→국민연금)** — 강력한 차별화지만 v2. 단, 데이터 모델은 이를 지원하도록 설계(§8)

## 5. 유저 스토리 (우선순위순)

- US1. 예비 파이어족으로서, 몇 개 숫자만 넣으면 **내가 몇 살에 은퇴 가능한지** 즉시 보고 싶다 — 계획의 출발점을 얻기 위해
- US2. 목표를 세운 유저로서, **매달 자산을 기록하면 계획보다 앞서는지/뒤처지는지** 보고 싶다 — 지루한 여정에서 동기를 유지하기 위해
- US3. 유저로서, "월 50만원 더 저축하면 몇 년 단축되는지" **변수를 만지며 즉시 결과**를 보고 싶다 — 저축 의사결정을 하기 위해
- US4. 구독자로서, 내 계획이 **시장 변동성 속에서도 성공할 확률**을 알고 싶다 — 계획의 건전성을 검증하기 위해
- US5. 한국 거주자로서, **국민연금 수령 전 브릿지 구간과 연금계좌**가 반영된 계산을 원한다 — 미국식 4% 룰만으로는 내 현실과 다르기 때문에
- US6. 유저로서, 홈 화면 위젯에서 **D-day와 진행률**을 매일 보고 싶다 — 앱을 열지 않아도 목표를 상기하기 위해
- US7. 유저로서, 폰을 바꿔도 **데이터를 안전하게 옮기고** 싶다 — 수년치 기록을 잃지 않기 위해
- US8. (엣지) 기록을 몇 달 건너뛴 유저로서, 죄책감 없이 **빈 달을 건너뛰고 재개**하고 싶다

## 6. 화면 단위 스펙

### 화면 맵

```
S0 스플래시 ─ S1 온보딩(입력) ─ S2 온보딩(결과+슬라이더) ─┐
                                                        ▼
   ┌──────────────── 하단 탭 ────────────────────────────────┐
   │ S3 홈(궤도)   S4 시뮬레이션   S5 기록(+)   S6 자산 뷰    │
   └──────────────────────────────────────────────────────┘
S7 목표 설정(상세)  S8 스냅샷 입력 플로우  S9 페이월  S10 설정  W1 위젯
S4-2 포트폴리오 구성(S4 내 모드 전환)
```

### S1. 온보딩 — 입력 (P0)

목적: 회원가입·권한 요청 없이 60초 안에 가치 도달. 4문항, 1문항 1화면, 키패드 자동 포커스.

입력: ① 나이 ② 세후 월소득 ③ 월 지출 ④ 현재 순자산(대략). 각 항목에 "대략이면 충분해요" 마이크로카피. 뒤로가기 가능, 이탈 시 값 보존.

수용 기준:
- [ ] 4문항 완료까지 어떤 계정/권한 요청도 없다
- [ ] 숫자 입력은 천 단위 콤마 자동 표기, 만원 단위 토글
- [ ] 앱 재실행 시 입력 중이던 단계에서 재개

### S2. 온보딩 — 결과 (P0) ★ aha moment

목적: 앱의 광고판. **"당신의 FIRE 나이: 52세"**를 큰 타이포로, 아래에 자산 성장 곡선(현재→FIRE 지점).

구성: FIRE 나이 헤드라인 / 필요 자산(FIRE Number)과 산출 근거 1줄("월 지출 300만 × 4% 룰 = 9억") / **What-if 슬라이더 1개(월 추가 저축)** — 움직이면 FIRE 나이가 실시간 갱신("+30만원 → 49세") / CTA "이 계획 시작하기" → 목표 저장 후 S3 진입.

수용 기준:
- [ ] 슬라이더 조작 → 결과 갱신 16ms 프레임 내 (재계산은 debounce 없이 즉시)
- [ ] 기본 가정(실질수익률 등)이 "가정 보기"로 투명하게 공개된다
- [ ] Given 지출>소득 입력, Then "현재 저축이 없어 FIRE 나이를 계산할 수 없어요" + 지출 조정 유도 (크래시·음수 연도 금지)

### S3. 홈 — 궤도 대시보드 (P0)

목적: 매달 돌아왔을 때 3초 안에 "나 잘 가고 있나"에 답한다.

구성 (위→아래):
1. **D-day 카운트다운**: "재정적 자유까지 11년 3개월" + FIRE 진행률 게이지(현재 자산/FIRE Number)
2. **궤도 차트**: 계획 곡선(점선) 위에 실제 스냅샷(점) 오버레이. 헤드라인 배지: **"계획보다 3개월 앞서는 중"** (편차 = 실제 자산이 계획 곡선상 도달 시점과의 시간차)
3. **이번 달 저축률**: 게이지 + 최근 6개월 미니 추이
4. 다음 기록까지 남은 날 / 기록 유도 카드 (미기록 월엔 최상단 고정)
5. 마일스톤 배너 (달성 시에만)

수용 기준:
- [ ] 스냅샷 2개 미만이면 궤도 편차 대신 "2번째 기록부터 궤도 비교가 시작돼요" 빈 상태
- [ ] 기록 3개월 공백 후 복귀 시 비난 톤 금지 — "다시 오셨네요, 이번 달만 기록하면 돼요" (US8)
- [ ] 모든 금액은 탭 1번으로 가림 처리(●●●) 토글 — 지하철에서 여는 앱임

### S4. 시뮬레이션 (P0 + 유료 훅)

목적: What-if 놀이터. 무료와 유료의 경계가 이 화면에 있다.

무료: 결정론 시뮬레이션 차트(월복리, 실질수익률), 슬라이더 3종(월 저축액/기대수익률/은퇴 후 월 생활비), 시나리오 저장 1개.

유료(🔒 표시 + 탭 시 S9): **몬테카를로 성공 확률** — 무료 유저에게도 요약 1줄 티저("이 계획의 성공 확률 87% — 상세 분포 보기 🔒"), 상세 분포 차트·자산 고갈 연령 분포는 구독 / 시나리오 무제한 저장·나란히 비교 / 은퇴 직후 폭락(시퀀스 리스크) 스트레스 테스트.

수용 기준:
- [ ] 몬테카를로 5,000회 × 60년이 UI 블로킹 없이 완료 (Dart isolate, 진행 인디케이터, 목표 1.5초 내)
- [ ] 시뮬 가정 변경은 저장 전까지 목표에 반영되지 않는다 (놀이터와 계획의 분리)
- [ ] 티저 확률 숫자는 무료에게도 정확한 값을 보여준다 (가짜 블러 금지 — 신뢰 원칙)

### S4-2. 시뮬레이션 — 포트폴리오 구성 (P1 + 유료 훅)

목적: 단일 수익률 가정을 자산군별 포트폴리오 가정으로 확장하는 What-if 심화. S4 안의 모드 전환(단순 ↔ 포트폴리오)으로 진입 — 새 탭 아님, 코어 루프(온보딩·기록)에는 노출하지 않는다 (MVP 단순함 보호).

구성: 자산군별 비중 슬라이더 + **합계 100% 스택 바** / 자산군 분류 — 주식형(S&P500·나스닥100·다우존스·국내주식·선진국/신흥국), 채권형(국고채·미국채(환노출 옵션)), 통화·현금성(달러(외환)·원화 예금), 대체(금·은·원자재·리츠) / **예시 구성 칩**(안정형·균형형·성장형·올웨더) / 결과 카드: 가중 기대수익률·변동성 → FIRE 나이·필요 자산 즉시 갱신("이 구성이라면 FIRE 나이 51세").

무료: 예시 구성 체험(비중 고정) + 결과 요약. 유료(🔒 표시 + 탭 시 S9): 비중 자유 편집, 자산별 가정 수익률 수정, 변동성 반영 몬테카를로, 포트폴리오 시나리오 나란히 비교.

수용 기준:
- [ ] 자산별 기대수익률 기본값은 과거 장기 평균 + 출처 명시. 앱의 '전망'이 아닌 유저가 수정 가능한 '가정'으로 취급, "가정 보기"로 항상 공개
- [ ] 프리셋 명칭·문구 어디에도 "추천" 표현 금지 — "예시 구성" + 사실 서술만 (투자자문 규제·스토어 심사 3.2.1(viii) 대비, 제품 원칙 4)
- [ ] 비중 합계가 100%가 아니면 반영 불가, 자동 정규화 제안 제공
- [ ] 1단계(v1.1): 가중 평균 실질수익률 `r = Σ(wᵢ × rᵢ)`로 기존 결정론 엔진 재사용 (엔진 변경 최소화). 2단계(v2): 자산군별 변동성·상관행렬 몬테카를로
- [ ] 결과에 면책 문구 유지 ("가정은 과거 장기 평균 기준 · 정보 제공 목적, 투자 자문 아님")

### S5→S8. 월 스냅샷 기록 플로우 (P0) ★ retention 심장

목적: 월 1회, 3분 안에 끝나는 리추얼. 탭바 중앙의 (+) 버튼.

플로우: ① 계좌/항목별 자산 입력 — **전월 값 복사 후 수정** 방식(첫 달만 항목 셋업: 예금·주식·연금계좌·부동산·대출(음수)·기타) ② 이번 달 소득/지출 합계 2필드 ③ 완료 → **결과 리빌 화면**: 순자산 증감 → 저축률 → 궤도 편차 갱신("계획보다 +3개월") → 마일스톤 달성 시 축하. 숫자가 순서대로 카운트업되는 연출.

수용 기준:
- [ ] 2번째 기록부터 평균 입력 시간 3분 이내 (전월 복사 기본값)
- [ ] 과거 월 소급 입력·수정 가능, 빈 달은 차트에서 선형 보간이 아닌 공백 처리
- [ ] 항목 추가/삭제/이름변경 자유, 항목별 자산군 태그(주식/채권/현금/부동산/연금/기타) — S6과 v2 인출모드의 기반
- [ ] 저장은 원자적(중간 이탈 시 draft 보존)

### S6. 자산 뷰 — 다중 관점 (P0 일부 + P1)

목적: 같은 자산을 여러 렌즈로. 상단 세그먼트 탭.

- **자산배분** (P0, 무료): 자산군 도넛 + 목표 배분 설정 시 편차 표시("주식 +5%p") — 사실 표시만, 행동 지시 문구 금지
- **현금흐름** (P0, 무료): 월 소득−지출=저축 막대, 저축률 추이
- **연금·세제** (P1, 유료): 연금저축+IRP 납입액의 세액공제 한도 대비 활용률, 국민연금 수령 전 브릿지 구간 시각화
- 배당/현금흐름 커버율 (P2)

### S7. 목표 설정 — 상세 (P0)

온보딩의 간이 가정을 정교화하는 곳. FIRE 유형 선택(Lean/Fat/Coast/Barista — 유형별 목표 공식 프리셋), 안전인출률(기본 4%, 3.0~5.0% 조정), 기대수익률·인플레(보수/중립/공격 프리셋 + 직접 입력), 은퇴 후 월 생활비, **국민연금 예상 수령액·수령 나이 입력**(통합연금포털에서 확인하는 방법 안내 링크) → 브릿지 구간 반영 계산.

수용 기준:
- [ ] 국민연금 입력 시: FIRE 자산 요구액이 "수령 전 구간(생활비 전액)"과 "수령 후 구간(생활비−연금)"으로 분리 계산된다
- [ ] 모든 가정 변경은 시뮬레이션 재계산과 홈 궤도(계획 곡선)에 반영, 변경 이력 보존(계획을 언제 바꿨는지 궤도 차트에 마커)

### S9. 페이월 (P0)

### S10. 설정 (P0)

### W1. 홈 화면 위젯 (P0 — 네이티브로 만드는 이유)

## 7. 시뮬레이션 엔진 요구사항 (P0)

- 월 단위 이산 시뮬레이션: `자산(t+1) = 자산(t) × (1+월수익률) + 월저축` , 은퇴 후엔 `− 월인출(인플레 연동)`
- 실질수익률 기준 계산(명목−인플레), 가정은 유저에게 항상 공개
- 몬테카를로: 월수익률 정규분포 샘플링(기대수익률·변동성 파라미터), 5,000회 기본, 성공 = 기대수명까지 자산>0. 시드 고정 옵션(동일 입력 → 동일 결과, 신뢰성)
- (S4-2) 포트폴리오 모드 1단계: 가중 평균 실질수익률 `r = Σ(wᵢ × rᵢ)`을 계산해 기존 결정론 엔진에 그대로 투입 — 신규 엔진 코드 최소. 2단계: 자산군별 변동성·상관행렬 기반 몬테카를로(촐레스키 분해 샘플링)로 확장. 자산군 프리셋(수익률·변동성·상관)은 정적 데이터로 내장 — 시세 연동 없음, 완전 로컬 원칙 유지
- 순수 Dart 모듈로 분리(UI 무의존) + 골든 테스트: 엑셀로 검증한 기준 케이스 20개와 오차 <0.1%

## 8. 데이터 모델 원칙 (v1.x 동기화 대비 — 아키텍처 보험)

- 모든 레코드: UUID PK(auto-increment 금지), `created_at`/`updated_at`, soft delete(`deleted_at`)
- 로컬 DB: SQLite(Drift). 금액은 정수(원 단위) — 부동소수점 금지
- 스키마 버전 관리 + 마이그레이션 테스트 (수기 데이터 수년치가 자산이므로 마이그레이션 실패 = 치명상)
- 자산 항목에 자산군 태그·계좌유형(일반/ISA/연금저축/IRP) 필드를 v1부터 포함 — v2 절세 인출 시뮬의 기반
